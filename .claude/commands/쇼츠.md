# 천반장 쇼츠 자동 제작 스킬

사용자가 주제와 내용을 주면, 기획 → 스크립트 → 나레이션 → 장면 영상 생성 → 조립까지
사용자 확인 없이 끝까지 자동으로 진행하고, 완성된 영상 파일을 전달한다.

## 사용법

```
/쇼츠 [주제와 전달할 내용]
```

예: `/쇼츠 BF인증 예비인증 서류 준비 방법. 필요한 서류 목록과 자주 반려되는 이유를 알려주고 천반장이 해결해준다는 톤으로`

## 고정 설정 (변경 금지 — 사용자가 명시적으로 바꾸라고 할 때만 변경)

| 항목 | 값 |
|---|---|
| 목소리 | `천반장_클립A_목소리` / voice_id `4450e6bb-53c7-498b-8d11-e0b528d73015` / voice_type `element` |
| TTS 엔진 | `text2speech_v2` + `variant: minimax` (자연스러운 한국어 발음). 실패 시 variant elevenlabs → seed_audio 순으로 폴백 |
| 캐릭터 | 천반장-베르데코 element `8c7a6ad5-07fc-4b0d-a5ab-973b45dbf4b1` (보라색 볼캡 정면 + 자켓 왼쪽 가슴에 베르데코 로고, 한국 여성). 구버전 `5e8c9770-…`(로고 없음)은 사용 금지 |
| 브랜딩 규칙 | 캐릭터 등장 컷 프롬프트에 반드시 포함: "verdeco logo on the cap front and left chest, no Adidas logo, no three stripes, no other brand marks". 안전모 착용 컷은 안전모 정면에 베르데코 로고 — 로고 element `<<<4a80391c-a154-45ad-acd7-3af4de983d34>>>`를 프롬프트에 함께 삽입 |
| 로고 | verdeco element `4a80391c-a154-45ad-acd7-3af4de983d34` (클로징 컷에만) |
| 포맷 | 9:16 세로, 1080x1920, 총 45~55초 |
| 자막 | **넣지 않는다** (사용자가 영상 검수 후 직접 작업) |
| 오프닝 시그니처 | "현장 문제? 천반장이 잡는다!" |
| 클로징 시그니처 | "설계부터 본인증까지, 천반장이 원스톱으로 해결합니다. 구독하고 현장에서 봅시다!" (주제가 BF인증이 아니면 "설계부터 본인증까지" 부분을 주제에 맞게 변형) |
| 스타일 키 | "bright clean corporate-vlog look, soft daylight, Korean construction site / office setting, crisp colors, shallow depth of field" — 모든 이미지 프롬프트에 동일하게 포함해 편 간 룩을 통일 |
| 도면 묘사 규칙 | 화면에 건축 도면·평면도가 나올 때는 반드시 **공공건물(관공서·학교·우체국·주민센터) 평면도**로 묘사 — 복도, 로비, 교실, 민원창구가 있는 대형 평면. **아파트 단위세대 평면 금지.** 프롬프트에 "public building floor plan (school / post office / government office) with corridors and lobby, NOT an apartment unit plan" 명시 |
| 화면 글자 규칙 | AI가 만드는 가짜 글자는 집중도를 떨어뜨린다. 문서·도면·간판의 글자는 **읽히지 않게** 처리(아웃포커스·원거리·비스듬한 각도). 모든 문서/도면 프롬프트에 "no readable text, no text labels, no gibberish lettering, papers out of focus" 포함. 읽히는 글자를 일부러 넣을 때만 정확한 한국어 문구를 따옴표로 프롬프트에 지정. 스크립트에 없는 임의 글자 절대 금지. 허용 로고는 베르데코뿐 |
| 금지 연출 | 도장 찍는 장면(문서에 스탬프 찍기) 금지 |

## 파이프라인

### 0단계: 작업 폴더 생성

`shorts/<YYYYMMDD>-<주제슬러그>/` 폴더를 만든다. 이하 모든 산출물은 여기에 저장.
영상·음성 바이너리는 git에 커밋하지 않는다(스크립트 md만 커밋).

### 1단계: 기획 + 스크립트

주제·내용을 바탕으로 `script.md` 작성:

- **나레이션 전문**: 한국어 130~150단어(45~55초 분량). 구조 = 훅(3초, 질문/충격 한 줄) → 오프닝 시그니처 → 본문(정보 전달 + 문제 해결 팁 2~3개) → 클로징 시그니처
- **톤**: 현장 반장 특유의 시원시원하고 자신감 있는 말투. 전문용어는 한 줄 풀이 동반
- **장면표**: 6~8컷, 컷당 5~8초. 각 컷에 [시간 / 화면 묘사 / 천반장 등장 여부] 기재
- **팩트체크**: 법령·수치가 나오면 WebSearch로 검증. 시설 유형별로 달라지는 세부 치수는 나레이션에서 숫자를 빼고 script.md에 메모로 남긴다
- **캡션 + 해시태그**: 유튜브 업로드용으로 script.md 하단에 포함

### 2단계: 나레이션 생성 (블록별 세그먼트)

> 주의: 이 원격 환경은 미디어 CDN(cloudfront/higgsfield) 다운로드가 이그레스 정책으로 차단되어
> 로컬 ffmpeg 조립이 불가능하다. 조립은 반드시 서버 측 `explainer_video` 도구로 한다.
> 따라서 나레이션은 통짜 1개가 아니라 **장면(블록)별 세그먼트로 나눠** 생성한다.

1. 나레이션을 장면표 기준으로 블록별 세그먼트로 분할 (대략 한글 40자 이내, 클로징만 길어도 됨)
2. 세그먼트마다 `generate_audio` 제출 — 병렬 제출 가능:
   `{model: "text2speech_v2", variant: "minimax", voice_id, voice_type}` (한국어 발음 자연스러움 우선.
   minimax 실패 시 elevenlabs, 그것도 실패하면 seed_audio로 폴백)
3. 나레이션 문장은 소리 내어 읽는 한국어 기준으로 작성: 숫자·영문 약어는 한글 발음으로 풀어 쓰기
   (예: "BF인증" → "비에프 인증", "1/12" → "십이분의 일"), 쉼표로 자연스러운 호흡 표시
4. 429(rate_limit)나 502가 나면 40~60초 뒤 재시도
5. **음성을 반드시 클립보다 먼저 완성**하고 각 세그먼트의 durationSec을 실측한다.
   3단계에서 각 클립 길이를 `해당 음성 길이 + 1~1.5초`(반올림)로 정확히 맞추기 위함 —
   장면 사이에 무음 간격(죽는 텀)이 생기지 않게 하는 핵심 규칙

### 3단계: 장면 클립 생성

각 컷마다:

1. `generate_image`로 키프레임 생성 (model: nano_banana_2 — 서버가 nano_banana_flash로 조정할 수 있음, 정상)
   - 천반장 등장 컷: 프롬프트에 `<<<8c7a6ad5-07fc-4b0d-a5ab-973b45dbf4b1>>>` 삽입 + 브랜딩 규칙 문구 포함
   - 클로징 컷: 로고 element `<<<4a80391c-a154-45ad-acd7-3af4de983d34>>>` 추가
   - 모든 프롬프트에 스타일 키 + "vertical 9:16 composition" 포함, aspect_ratio "9:16"
2. 키프레임을 입력으로 `generate_video` (model: wan2_7, aspect_ratio "9:16",
   medias: [{role:"start_image", value:"<이미지 잡 ID>"}])
   - **duration = 해당 블록 음성 길이 + 1~1.5초 (반올림, wan2_7는 2~15초 임의 지정 가능).**
     고정 7초 금지 — 음성보다 클립이 길수록 장면 사이 무음 텀이 생긴다
   - 같은 클립을 두 블록에 재사용하지 말 것 — 같은 키프레임에서 모션 프롬프트를 바꿔 별도 생성
   - 프롬프트에 "She does not speak" 포함 (나레이션과 입모양 충돌 방지)
   - `preset_recommendation` 알림이 오면 사용자에게 묻지 말고 `declined_preset_id`를 넣어 원래 프롬프트로 즉시 재제출
   - 429는 40~60초 뒤 재시도. 잡은 병렬 제출
3. 완료 폴링: `show_generations`로 일괄 확인 (2~4분 소요)
4. 실패한 잡은 프롬프트를 다듬어 1회 재시도

### 4단계: 조립 (서버 측, explainer_video)

1. `explainer_video`에 블록 배열 전달: `items: [{video: "<클립 잡ID>", audio: "<세그먼트 음성 잡ID>"}, ...]` 재생 순서대로
2. `width`/`height`는 클립 실제 해상도 사용 (wan2_7 720p 9:16 = 768x1344)
3. **`subtitles` 파라미터는 절대 넣지 않는다** (자막 없음)
4. 짧은 음성은 블록 중앙 배치, 살짝 긴 음성은 피치 유지 배속 — 도구가 자동 처리

### 5단계: 전달 및 마무리

1. 조립 잡 완료 후 `job_display`로 최종 영상을 위젯에 표시하고 영상 URL도 함께 보고
   (CDN 차단 때문에 로컬 다운로드/SendUserFile 불가 — Higgsfield 위젯/URL로 전달)
2. `script.md`만 git 커밋·푸시 (지정된 작업 브랜치)
3. 보고: 블록 구성, 소요 크레딧, 실패/대체된 컷이 있으면 명시

## 원칙

- 1~5단계는 중간 확인 없이 끝까지 자동 진행한다. 질문으로 멈추지 않는다
- 단, 주제가 모호해서 스크립트 방향이 두 갈래 이상으로 갈리면 1단계에서만 짧게 확인
- 여러 주제가 한 번에 들어오면(예: 5개) 편마다 폴더를 나눠 순차 제작
- 크레딧 잔액이 1편 제작에 부족해 보이면 시작 전에 `balance`로 확인하고 사용자에게 알린다
